## 4. Core thesis

The investment is the direction.
The deal is the structure.
EXEL connects them around the person.

Public communication should generally lead with aspiration, opportunity, investment, future and human value, then prove the promise through deal structure, evidence, fit, scenarios, documents and process.

Default editorial balance:

- ~60% investment / possibility / desire
- ~40% transaction / proof / structure

This is a journey-level principle, not a formula for every paragraph.

## 8. Layered language architecture

EXEL communication operates in four layers:

1. Marketing / Desire — creates desire and relevance.
2. Intelligence / Value — explains the mechanism and gives real value.
3. Proof / Evidence — reduces uncertainty through evidence.
4. Action / Progression — converts trust into a clear next step.

Default rhythm:

Marketing → Value → Proof → Action.

QA must score two separate axes:

- Brand Magnetism
- Professional Depth

Control question:

Did we build enough desire for the person to want to continue — and enough depth for them to understand why continuing makes sense?

## 10. Decision grammar

Active decision grammar:

Person / goal → deal mechanism → source / status → assumptions / dependencies → capital timing → professional owner → open questions → scenario / review point → decision relevance → next step.

A good result does not retroactively prove a good decision.
EXEL evaluates the quality of the process using the information available at the time.

## 11. Evidence standard

Every material promise should point to an object that can be shown:

- source
- date
- document
- calculation
- status
- owner
- scope
- deliverable
- timeline
- open question
- verified workflow

Trust seal `נדל״ן שנבדק.` is permitted only after an Evidence Gate with defined scope, sources, date, responsibility and open questions.

## 12. Claims guardrails

Never promise:

- guaranteed return
- zero risk
- certain appreciation
- guaranteed financing
- guaranteed discount
- guaranteed commercial result

Separate clearly:

- fact
- verified fact
- assumption
- scenario
- potential
- pending verification
- open question

## 25. Canonical operating rule

For every material EXEL task:

READ → ALIGN → EXECUTE → DECIDE → WRITE BACK → VERIFY.
